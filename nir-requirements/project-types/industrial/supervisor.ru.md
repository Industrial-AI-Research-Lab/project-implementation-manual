# Индустриальный проект — нюансы для руководителя

Этот файл дополняет общие требования. В индустриальном проекте руководитель должен обеспечить связь работы с реальным процессом и возможность измерить эффект.

## До утверждения темы

Нужно определить:

- индустриального заказчика/пользователя;
- конкретный процесс и болевую точку;
- существующий способ решения или текущий процесс как baseline;
- измеримые критерии эффекта;
- доступность данных и реалистичность проверки;
- ограничения внедрения;
- представителя индустрии, который сможет дать содержательную рецензию.

Индустриальная тема формулируется представителем индустрии-заказчиком.

## Метрики

В зависимости от задачи подходят не только ML-метрики, но и:

- сокращение времени процесса;
- снижение трудозатрат;
- стоимость обработки/инференса;
- рост throughput;
- уменьшение failure rate;
- повышение точности принятия решений;
- экономический эффект;
- снижение вычислительных или организационных ресурсов.

## Что контролировать по ходу проекта

- решение сравнивается с текущим процессом, а не только с другой моделью;
- пользовательский/производственный сценарий остаётся реалистичным;
- ограничения данных и инфраструктуры явно фиксируются;
- технический прототип достаточен, чтобы подтвердить заявленный эффект;
- рецензия индустрии готовится не формально в последний день, а опирается на демонстрацию/результаты.

## Критические риски оценки

- отсутствие обязательной индустриальной рецензии → максимум 4В;
- отсутствие количественного эффекта и сравнения → не выше общего ограничения 4С;
- гипотетическое «можно внедрить» без анализа ограничений не является высоким потенциалом внедрения;
- проект, где нет реального/реалистичного пользователя и процесса, теряет смысл индустриального типа.

## Что должно быть видно в финале

Комиссия должна быстро понять: **кто пользователь → какая проблема → как решают сейчас → что предложено → какой измеримый эффект → насколько реально внедрение → чем это подтверждено заказчиком.**
