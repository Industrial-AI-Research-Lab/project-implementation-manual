# Репозиторий и работа с кодом — памятка руководителю

С этой памяткой у вас будут репозиторий, который запускается из чистого клона, ревью, после которых остаётся история обсуждения, и чек-лист контрольной точки, связывающий состояние репозитория с оценкой. Правила работы описаны в [памятке студенту](student.ru.md); здесь — то, что по этим правилам делаете вы.

## Термины

| Термин | Пояснение | Что это значит для вас |
|---|---|---|
| Pull request (PR), Draft, Ready for review | PR — предложение влить изменения из ветки в `main` вместе с описанием и обсуждением на ревью. Статус Draft означает, что работа не закончена; Ready for review — что PR ждёт ревью. | Вы смотрите PR в статусе Ready; Draft — студент ещё работает над PR. |
| CODEOWNERS | В файле `.github/CODEOWNERS` указано, кто ревьюит какие пути; когда PR переходит в статус Ready for review, GitHub запрашивает ревью у этих людей. | Когда файл попадёт в `main`, строки с вашим handle хватит, чтобы вас назначали ревьюером каждого PR; на тарифе Free это работает только в публичном репозитории. |
| Ruleset, защита ветки | Настройки репозитория, которые запрещают прямые push в `main` и требуют PR, аппрув, закрытые обсуждения или зелёные проверки. | В публичном репозитории доступны бесплатно; в приватном те же правила держатся только на договорённости. |
| ADR, журнал решений, статусы | Запись архитектурного решения — один файл на решение: контекст, варианты, решение, последствия. Статусы: proposed, accepted, rejected, superseded. | Записи решений вы проверяете в PR так же, как код; если предложенный вами вариант отклонили, в записи должна быть указана причина. |
| Эксперимент, запуск, тег | Термины MLflow: эксперимент объединяет запуски; запуск — одно выполнение со своими параметрами, метриками, артефактами и тегами, в том числе тегом с коммитом. | Если у результата нет id запуска, сделанного на коммите из PR, результат считается непроверенным. |
| `.env.example` | Закоммиченный список ключей конфигурации с заглушками; настоящий `.env` игнорируется. | По заполненным ключам видно, какие доступы у студента уже есть; чтобы запустить проект, скопируйте этот файл в `.env`. |

## Первая неделя

Договоритесь со студентом о порядке работы и попросите записать его в README репозитория или в шаблон PR: все изменения идут только через PR или мелкие правки можно вносить прямо в `main` (тогда ruleset не должен требовать PR); в какой срок отвечать на ревью; кто закрывает обсуждения.

Список ниже — напоминание, чтобы ничего не упустить; что из него нужно в вашем проекте, решаете вы:

- принять приглашения: в репозиторий в роли collaborator и в GitHub Project студента в роли Admin;
- попросить студента смержить шаблон PR, а в публичном репозитории ещё и `.github/CODEOWNERS` с вашим handle и настроить ruleset для `main` в соответствии с договорённостью: обязательный PR, один аппрув, закрытые обсуждения, зелёные проверки; в приватном репозитории студент назначает вас ревьюером сам;
- выдать доступы к LLM-шлюзу лаборатории, VPN и кластеру; сообщить, есть ли общий сервер MLflow и хранилище артефактов, и передать их адреса и учётные данные, иначе студент будет сохранять запуски в локальную базу; по заполненному `.env.example` в репозитории видно, какие доступы у студента уже есть;
- если проекту нужен тестовый стенд, помочь его развернуть или дать доступ к лабораторному;
- один раз согласовать со студентом обязательные теги MLflow и формат строки результата.

## Ревью

- Сначала читайте описание PR: сверьте разделы План и Сделано, проверьте Как воспроизвести и `Closes #N`. Если раздела Сделано нет или не указан id запуска, верните PR, не читая код.
- Отправляйте все комментарии разом через Start a review. В первом раунде обсуждайте архитектуру и декомпозицию, а имена и стиль — позже или с пометкой non-blocking.
- Помечайте каждый комментарий: blocking или non-blocking, `nit:` — для замечаний на вкус. К каждому замечанию предлагайте вариант исправления. Аппрувьте с комментариями, когда остались только мелочи.
- Если код непонятен, просите переписать его яснее, а не объяснять в обсуждении: объяснению место в коде или в записи решения.
- Закрывайте обсуждения сами, когда проверите коммит с исправлением; GitHub позволяет закрывать их и автору PR, поэтому сразу предупредите студента, что закрываете их вы.
- В каждом PR, который трогает код моделей, проверяйте: есть запуск MLflow на коммите из ветки PR, и его эксперимент назван в описании; запись решения, когда сменились библиотека, бейзлайн, метрика или датасет; в диффе нет данных, весов и секретов; CI зелёный.
- Перед каждой контрольной точкой сами запускайте команды из README в чистом клоне.
- Не вставляйте неопубликованный код студента во внешний LLM-сервис без согласия студента.

## Оценка

Критерии репозитория и формальные ограничители описаны в [общих требованиях](../../general/student.ru.md): результат, который нельзя проверить по репозиторию, ограничивает оценку уровнем 4C, отсутствие обязательного артефакта — уровнем 4B, отсутствие рабочего результата — уровнем 3E. В середине семестра скажите студенту, какой ограничитель действует сейчас и что нужно сделать, чтобы его снять.

## После защиты

- Не выходите из числа collaborator: история репозитория подтверждает выполненную работу.
- Попросите студента поставить финальный тег на `main`, почистить эксперименты командой `mlflow gc` и указать в README пути к данным и артефактам.
- Переносите репозиторий в организацию лаборатории, только если код нужен в её проекте: студент вступает в организацию и запускает перенос в настройках репозитория; issues, PR, секреты и редиректы переезжают вместе с репозиторием; Project остаётся у студента, его нужно скопировать.

## Чек-лист контрольной точки

- [ ] Команды из README работают из чистого клона.
- [ ] В описании каждого PR, смерженного за период, есть разделы План, Сделано, Как воспроизвести и `Closes #N`.
- [ ] У каждого PR с кодом моделей есть запуск MLflow на коммите его ветки с обязательными тегами.
- [ ] В `docs/adr/` есть запись по каждому решению, принятому за период; статусы актуальны.
- [ ] `make check` проходит локально, CI зелёный на `main`.
- [ ] В истории нет секретов, данных и весов; `.env.example` актуален.
- [ ] Студент знает, какой ограничитель оценки действует сейчас.
