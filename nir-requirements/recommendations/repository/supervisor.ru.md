# Репозиторий и работа с кодом — памятка руководителю

Что вы получаете: репозиторий, который запускается из чистого клона, цикл ревью, который оставляет след, и список контрольной точки, который связывает состояние репозитория с оценкой. Конвенции описаны в [памятке студенту](student.ru.md); здесь ваша сторона этих конвенций.

## Термины

| Термин | Пояснение | Что это значит для вас |
|---|---|---|
| Pull request (PR), Draft, Ready for review | PR предлагает изменение из ветки в `main`, с описанием и обсуждением ревью. Draft помечает незаконченную работу; Ready for review запрашивает ревьюера. | Вы смотрите PR в статусе Ready; Draft — работа студента в процессе. |
| CODEOWNERS | Файл `.github/CODEOWNERS` сопоставляет пути ревьюерам; GitHub запрашивает их, когда PR становится Ready for review. | Одна строка с вашим handle делает вас ревьюером каждого PR после мержа файла в `main`. |
| Ruleset, защита ветки | Настройки репозитория, которые запрещают прямые push в `main` и требуют PR, аппрув, закрытые обсуждения или зелёные проверки. | Бесплатно на публичном репозитории; на приватном те же правила держатся только на договорённости. |
| ADR, журнал решений, статусы | Запись архитектурного решения — один файл на решение: контекст, варианты, решение, последствия. Статусы: proposed, accepted, rejected, superseded. | Вы проверяете записи в PR как код; отвергнутая ваша альтернатива должна появиться с причиной. |
| Эксперимент, запуск, тег | Словарь MLflow: эксперимент группирует запуски; запуск — одно выполнение с параметрами, метриками, артефактами и тегами, включая коммит. | Результат без id запуска на коммите PR не проверен. |
| `.env.example` | Закоммиченный список ключей конфигурации с заглушками; настоящий `.env` игнорируется. | Заполненные ключи показывают, какие доступы есть у студента; вы копируете его в `.env`, чтобы запустить проект. |

## Первая неделя

Договоритесь со студентом о режиме и попросите записать его в README репозитория или в шаблон PR: всё через PR или мелкие правки в `main` разрешены; сроки ответа; кто закрывает обсуждения.

Напоминание, чтобы ничего не забыть; что из этого нужно в каждом случае, решаете вы:

- принять приглашения: collaborator в репозитории, Admin в GitHub Project студента;
- попросить студента смержить `.github/CODEOWNERS` с вашим handle и шаблон PR, а на публичном репозитории поставить ruleset на `main`: обязательный PR, один аппрув, закрытые обсуждения, зелёные проверки;
- доступы: LLM-шлюз лаборатории, VPN, кластер; скажите, есть ли общий сервер MLflow и хранилище артефактов, и передайте их адреса и учётные данные, иначе студент пишет запуски в локальную базу; заполненный `.env.example` в репозитории показывает, что у студента есть;
- тестовый стенд, когда он нужен проекту: помочь развернуть или указать на лабораторный;
- обязательные теги MLflow и формат строки результата, согласованные один раз.

## Ревью

- Сначала читайте описание PR: План против Сделано, Как воспроизвести, `Closes #N`. Если Сделано отсутствует или id запуска не указан, верните PR до чтения кода.
- Комментируйте одним пакетом через Start a review. Первый раунд по дизайну и декомпозиции; имена и стиль позже или с пометкой non-blocking.
- Помечайте каждый комментарий: blocking или non-blocking, `nit:` для вкуса. К замечанию прикладывайте предложение. Аппрувьте с комментариями, когда остались только мелочи.
- Просите более ясный код вместо объяснения в обсуждении; объяснению место в коде или в записи решения.
- Закрывайте обсуждения сами после проверки исправляющего коммита; GitHub позволяет закрыть их и автору, поэтому скажите один раз, что это делаете вы.
- В каждом PR, который трогает код моделей, проверяйте: запуск MLflow, чей коммит лежит в ветке PR и чей эксперимент назван в описании; запись решения, когда сменились библиотека, бейзлайн, метрика или датасет; в диффе нет данных, весов и секретов; CI зелёный.
- Раз в контрольную точку сами запустите команды из README из чистого клона.
- Не вставляйте неопубликованный код студента во внешний LLM-сервис без его согласия.

## Оценка

Критерии репозитория и формальные ограничители описаны в [общих требованиях](../../general/student.ru.md): результат, который нельзя проверить по репозиторию, ограничивает оценку 4C, отсутствующий обязательный артефакт — 4B, отсутствие рабочего результата — 3E. В середине семестра скажите, какой ограничитель действует сейчас и что его снимает.

## После защиты

- Останьтесь collaborator; история — это доказательство.
- Попросите финальный тег на `main`, `mlflow gc` по экспериментам и пути к данным и артефактам в README.
- Перенос в организацию лаборатории только когда код нужен в проекте лаборатории: студент запускает его из настроек репозитория после вступления в организацию; issues, PR, секреты и редиректы переезжают вместе с ним; Project остаётся у студента и копируется.

## Чек-лист контрольной точки

- [ ] Команды из README работают из чистого клона.
- [ ] Смерженные PR периода содержат План, Сделано, Как воспроизвести, `Closes #N`.
- [ ] У каждого PR с кодом моделей есть запуск MLflow на коммите его ветки с обязательными тегами.
- [ ] В `docs/adr/` есть запись по каждому решению периода; статусы актуальны.
- [ ] `make check` проходит локально, CI зелёный на `main`.
- [ ] В истории нет секретов, данных и весов; `.env.example` актуален.
- [ ] Действующий ограничитель оценки озвучен студенту.
