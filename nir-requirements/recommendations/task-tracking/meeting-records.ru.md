# Записи встреч — справка

Необязательная справка к [памятке о трекинге задач](student.ru.md): как получить хорошую расшифровку встречи, как очистить её перед публикацией и какими промптами превратить её в запись встречи.

## Термины

| Термин | Пояснение | Что это значит для вас |
|---|---|---|
| Расшифровка, таймкод | Текст встречи по репликам; таймкод — время реплики от начала записи. | По таймкоду любое решение можно проверить на записи. |
| Диаризация | Разметка расшифровки по говорящим: кто какую реплику сказал. | Без неё модель не отличит решение руководителя от предложения студента. |
| WER (word error rate) | Доля слов, распознанных с ошибкой; чем меньше, тем лучше. | Сравнивайте инструменты по WER на русской речи, а не по обещаниям на сайте. |
| Санитизация, псевдонимизация | Санитизация — удаление из текста сведений, которые нельзя публиковать. Псевдонимизация — замена имён ролями по таблице соответствия. | По 152-ФЗ замена имён ролями при сохранённой таблице соответствия считается обезличиванием, а не полной анонимизацией. |

## Файл встречи

```markdown
# Встреча YYYY-MM-DD

Участники: студент, руководитель
Запись: <ссылка на запись в Толке>

## Решения
- <решение> (12:34)

## Задачи
- [ ] <задача> — <ответственный>, <срок>, #<номер issue>

## Открытые вопросы
- <вопрос>

Следующая встреча: YYYY-MM-DD
```

## Расшифровка

Встроенной расшифровки Толка обычно хватает. Если вы ей не доверяете или записывали встречу другим инструментом, выберите вариант из таблицы.

| Инструмент | Где работает | Говорящие | Что нужно |
|---|---|---|---|
| Контур.Толк (используется в ИТМО) | облако, Россия | по именам участников | облачная запись; TXT с говорящими и таймкодами: «Артефакты → Видеозаписи → скачать → Транскрипция» |
| faster-whisper с моделью Whisper large-v3 | локально | нет | видеокарта примерно с 3 ГБ памяти в режиме int8 или долгий расчёт на процессоре |
| WhisperX | локально | да, через pyannote | токен Hugging Face и согласие с условиями использования модели pyannote |
| GigaAM-v3 | локально | нет | для записей длиннее 25 секунд — доступ к модели pyannote/segmentation-3.0 |

- Для русской речи разработчик GigaAM-v3 приводит средний WER 8,4 % против 25,1 % у Whisper large-v3 на своих наборах данных. Независимые сравнения показывают, что какая модель точнее, зависит от типа записи.
- Облачные API вроде Yandex SpeechKit стоят недорого, около 36 ₽ за час двухканального аудио на сентябрь 2026 года, но требуют платёжного аккаунта.

Звук из видеозаписи достаньте так:

```bash
ffmpeg -i meeting.mp4 -vn -ar 16000 -ac 1 -c:a pcm_s16le meeting.wav
```

Расшифровка через faster-whisper с таймкодами:

```python
from faster_whisper import WhisperModel

model = WhisperModel("large-v3", device="cuda", compute_type="int8_float16")
segments, info = model.transcribe(
    "meeting.wav",
    language="ru",
    vad_filter=True,
    initial_prompt="MLflow, baseline, ablation, <термины и названия вашего проекта>",
)
with open("meeting.txt", "w") as f:
    for s in segments:
        f.write(f"[{int(s.start // 60):02d}:{int(s.start % 60):02d}] {s.text.strip()}\n")
```

Расшифровка с разметкой по говорящим через WhisperX:

```bash
whisperx meeting.wav --model large-v3 --language ru --diarize --min_speakers 2 --max_speakers 2 --hf_token "$HF_TOKEN" --output_format srt
```

Как повысить качество расшифровки:

- Говорите по очереди, в гарнитуру или в микрофон у рта: одновременную речь модели распознают и делят по говорящим хуже всего.
- Указывайте язык явно: `language="ru"`.
- Передайте модели названия библиотек, моделей и датасетов проекта через подсказку (`initial_prompt`): так она реже искажает термины.
- Имена, числа и термины сверяйте с записью вручную.

## Санитизация

Предупредите участников, что встреча записывается и что часть записи вы опубликуете в репозитории; если кто-то против, не записывайте. Затем:

- Имена всех, кроме студента и руководителя, замените ролями в квадратных скобках: [эксперт партнёра], [одногруппник]. У каждого человека во всех файлах одна и та же метка.
- Косвенные признаки обобщите: вместо должности, возраста или названия компании пишите общие метки вроде [сотрудник банка] или [промышленный партнёр].
- Полностью удалите пароли, ключи и токены, внутренние адреса и ссылки, данные партнёра под NDA, оценки, упоминания здоровья и других личных тем, а также разговоры не по делу.
- Таблицу соответствия меток и имён храните отдельно и не коммитьте.
- Автоматический поиск помогает, но может пропустить часть данных: Natasha находит имена, организации и места, регулярные выражения — почты и телефоны, `gitleaks dir docs/meetings` — ключи и токены. После него перечитайте текст сами.
- Неочищенную расшифровку обрабатывайте локальной моделью или сервисом, который хранит данные в России.

Что говорит закон (для ориентира). По 152-ФЗ персональные данные — любые сведения, которые прямо или косвенно указывают на человека. Публикация в открытом репозитории считается распространением, а для него нужно отдельное согласие человека. С 1 июля 2025 года персональные данные граждан России при сборе нельзя записывать и хранить в базах за пределами страны, поэтому хранить полную расшифровку на зарубежной платформе рискованно. Это наше толкование, не юридическая консультация.

## Промпты

Длинный текст ставьте в начало запроса, инструкции — после него. Просите модель опираться только на расшифровку и указывать таймкод для каждого решения.

**Очистка расшифровки.**

```text
<transcript>…</transcript>
Исправь ошибки распознавания в терминах из списка: <термины проекта>. Не меняй смысл, не сокращай и не добавляй реплики. Неразборчивые места помечай [неразборчиво, ММ:СС].
```

**Санитизация.**

```text
<transcript>…</transcript>
Замени имена всех участников, кроме студента и руководителя, ролями в квадратных скобках; у каждого человека везде одна и та же метка. Удали пароли, ключи, токены, внутренние адреса, данные партнёра, оценки и личные темы. Верни очищенный текст, а отдельно — таблицу «исходное имя → метка».
```

**Запись встречи.**

```text
<transcript>…</transcript>
Используй только эту расшифровку, не свои знания.
1. Дословно выпиши реплики, в которых принято решение или поставлена задача, с таймкодом и именем говорящего.
2. По этим цитатам заполни шаблон файла встречи: решения с таймкодами, задачи с ответственным и сроком, открытые вопросы.
Если ответственный или срок не названы, пиши «не указано». Если сомневаешься, было ли это решением, помечай [проверить].
```

**Задачи для доски.**

```text
<transcript>…</transcript>
Перечисли в JSON задачи, о которых договорились на встрече, с полями title, owner, deadline, timecode. Бери только задачи, с которыми согласились обе стороны.
```

Затем попросите ассистента завести каждую задачу из списка командой `gh issue create --project`.

**Проверка записи.**

```text
<transcript>…</transcript>
<summary>…</summary>
Сверь запись встречи из <summary> с расшифровкой и найди в ней ошибки: пропущенные решения, выдуманные решения, неверно названного говорящего, неверные числа и сроки. Для каждой ошибки укажи таймкод. Затем исправь только найденные ошибки.
```

Если сомневаетесь в результате, запустите проверку дважды и сравните ответы: расхождения покажут, где модель что-то выдумала.
