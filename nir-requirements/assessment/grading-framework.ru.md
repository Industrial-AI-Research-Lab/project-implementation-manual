# Новое по проектам — Markdown-версия

## Дополнительный формат: групповой проект

Дополнительный формат, только по заявке от руководителя НИР — групповой проект.

Студенты не могут самостоятельно собираться в группу для выполнения проекта.

Только для студентов 1 курса.

### Что оценивается?

- масштаб и степень проработки задачи;
- соответствие объёма проекта числу участников: объём и сложность группового проекта должны соответствовать суммарному объёму работ, который мог бы быть выполнен участниками индивидуально;
- научная и/или технологическая новизна;
- технический уровень и качество реализации;
- целостность результата и согласованность решений, выполненных разными участниками;
- степень готовности результата к практическому применению и/или дальнейшему развитию;
- способность участников работать в команде и соблюдать сроки.

### Требуемые результаты

- открытый репозиторий с кодом реализации проекта, содержащий результаты работы всех участников (все участники проекта должны быть контрибьюторами с возможностью оценки авторства блоков кода);
- презентация с описанием общей постановки задачи, архитектуры решения, распределения работ между участниками, хода реализации и основных полученных результатов;
- индивидуальный отчёт каждого участника, содержащий описание выполненной им части проекта, её результатов и личного вклада;
- описание распределения задач между участниками и взаимосвязей между отдельными компонентами проекта;
- демонстрация работающего результата (при наличии применимого программного или технологического продукта);
- оценка вклада каждого участника руководителем проекта и/или членами команды;
- личный вклад каждого участника: соответствие фактически выполненной работы заявленной роли, сложность и самостоятельность выполненных задач;
- при необходимости — подтверждение индивидуального вклада через историю коммитов, issue/task-трекер, результаты экспериментов, документацию и другие артефакты.

### Особенности

Групповой проект предполагает выполнение единой комплексной задачи, объём и сложность которой должны быть сопоставимы с суммарным объёмом работ, предусмотренным для индивидуальных проектов всех участников группы. Таким образом, проект группы из N участников должен содержать объём работы, эквивалентный N индивидуальным проектам. Каждый участник должен иметь самостоятельную, содержательно значимую часть работы, результаты которой могут быть идентифицированы и оценены отдельно.

Механическое разделение одной задачи на несколько небольших частей не является достаточным основанием для признания проекта групповым. Индивидуальный вклад каждого участника должен включать самостоятельные задачи, требующие применения профессиональных компетенций программы, а результаты отдельных участников должны быть интегрированы в единый итоговый результат проекта.

Руководителю не надо делить задачу на подтемы.

Студентам про этот тип проекта не говорим, пока не будет заявок от руководителей.

# Расширенные критерии оценивания НИР магистров

## 1. Общие принципы оценивания

Оценивание проекта осуществляется по шести уровням:

- **5А** — отлично / проект высокого уровня, все требования выполнены в полном объёме;
- **4В** — хорошо / высокий уровень, но требования выполнены не в полном объёме;
- **4С** — хорошо / достаточно высокий уровень;
- **3D** — удовлетворительно / минимально достаточный уровень;
- **3E** — удовлетворительно / погранично достаточный уровень;
- **2FX** — неудовлетворительно / результат требует существенной доработки.

Оценка определяется не только количеством выполненной работы, но и совокупностью следующих характеристик:

1. актуальность и обоснованность постановки задачи;
2. степень проработки задачи;
3. качество и самостоятельность полученного результата;
4. качество экспериментальной или практической проверки;
5. наличие и качество сравнения с существующими решениями и аналогами;
6. качество кода и репозитория;
7. качество основного текстового артефакта;
8. качество презентации и доклада;
9. способность студента объяснить принятые решения и полученные результаты;
10. соответствие результата заявленному типу проекта;
11. для группового и коллаборативного проектов — качество командной работы и индивидуальный вклад.

## Обязательные условия для оценки 5А

Оценка 5А не может быть выставлена, если отсутствует хотя бы одно из следующих принципиальных условий.

### 1. Представлены все обязательные артефакты

Проект должен содержать все артефакты, предусмотренные для соответствующего типа проекта:

- репозиторий с кодом — если он предусмотрен типом проекта;
- научный препринт / технологический отчёт / описание решения;
- презентацию;
- рецензию индустриального партнёра — для индустриального проекта;
- оценку командного вклада — для коллаборативного проекта;
- индивидуальный отчёт о вкладе — для группового проекта.

Отсутствие обязательного артефакта автоматически ограничивает максимальную оценку ниже 5А.

Наличие ссылки само по себе не считается наличием качественного артефакта: артефакт должен содержательно соответствовать требованиям проекта.

### 2. Проведено сравнение с существующими решениями

Для получения 5А необходимо показать, чем предложенное решение отличается от существующих подходов и насколько оно эффективно относительно них.

Сравнение должно включать:

- релевантные существующие методы, алгоритмы, модели, системы или инструменты;
- чётко определённые метрики;
- одинаковые или сопоставимые условия эксперимента;
- количественные результаты;
- интерпретацию полученных различий.

Формулировка «наш метод лучше» без количественного подтверждения не является сравнением.

Примеры допустимого сравнения:

- качество: Accuracy, F1, ROC-AUC, BLEU, ROUGE, pass@k и т. п.;
- скорость: latency, throughput;
- вычислительная эффективность: время обучения, GPU hours, memory;
- стоимость: количество токенов, стоимость API-вызовов, стоимость инференса;
- надёжность: failure rate, success rate;
- качество генерации: task success rate, human evaluation;
- для индустриальных задач — бизнес-метрики, экономический эффект, сокращение времени или ресурсов.

Если сравнение с аналогами отсутствует, оценка 5А невозможна.

### 3. Результат воспроизводим

Другой исследователь или разработчик должен иметь возможность понять:

- какие данные использовались;
- как подготовлены данные;
- какая модель/алгоритм использовались;
- какие параметры выбраны;
- как запустить код;
- как получить основные результаты;
- какие ограничения есть у эксперимента.

### 4. Студент понимает собственную работу

На защите студент должен самостоятельно и уверенно объяснить:

- постановку задачи;
- используемый метод;
- архитектуру решения;
- ключевые алгоритмы;
- экспериментальный дизайн;
- метрики;
- бейзлайн;
- результаты;
- ограничения;
- причины полученных результатов.

Наличие работающего кода не компенсирует отсутствие понимания собственного решения.

Если студент не может объяснить существенную часть своей работы, это является основанием для снижения оценки независимо от наличия артефактов.

# Оценивание по типам проекта

## Научный проект

### Что оценивается

- научная новизна;
- корректность постановки научной задачи;
- качество обзора существующих подходов;
- обоснованность предложенного метода;
- качество экспериментов;
- сравнение с бейзлайном и/или SOTA;
- статистическая и методологическая обоснованность результатов;
- готовность результата к публикации;
- воспроизводимость.

### 5А — научный результат высокого уровня

Студент получил содержательно новый научный результат, который убедительно подтверждён экспериментально или теоретически, при этом требования к постановке задачи, результатам, их обоснованию и представлению выполнены в полном объёме.

Характеристики:

- проблема актуальна и чётко сформулирована;
- показано, какие ограничения имеют существующие методы;
- сформулирована конкретная научная гипотеза или исследовательский вопрос;
- научная новизна явно сформулирована и понятна;
- предложенный метод/подход имеет самостоятельный содержательный вклад;
- проведено полноценное сравнение с релевантными аналогами;
- используются количественные метрики;
- присутствует сильный бейзлайн и, где возможно, современные SOTA методы;
- проведён ablation study или другой анализ вклада компонентов;
- экспериментальный дизайн позволяет сделать обоснованные выводы;
- результаты устойчивы и интерпретируемы;
- ограничения исследования явно описаны;
- представлен полноценный препринт научной статьи;
- репозиторий позволяет воспроизвести основные эксперименты;
- все обязательные артефакты представлены;
- презентация логична, визуально понятна и содержит именно те результаты, которые позволяют оценить научный вклад;
- студент уверенно отвечает на вопросы комиссии.

**Обязательное условие:** отсутствие количественного сравнения с существующими решениями не позволяет поставить 5А.

### 4В — сильный научный результат

Работа выполнена на хорошем научном уровне, однако присутствуют отдельные недостатки, требования к постановке задачи, результатам, их обоснованию и представлению выполнены не в полном объёме.

Возможны:

- интересная научная постановка;
- содержательный собственный метод;
- корректные эксперименты;
- сравнение с несколькими бейзлайнами;
- количественные метрики;
- убедительные результаты.

Но при этом:

- экспериментальная часть может быть недостаточно полной;
- может не хватать части сравнений;
- анализ вклада компонентов (ablation study) может быть ограниченным;
- исследование проведено на недостаточно широком наборе данных;
- отдельные результаты требуют дополнительного подтверждения;
- статья может быть не полностью готова к подаче.

При этом студент понимает научную постановку и способен объяснить полученные результаты.

### 4С — хороший результат с существенными недоработками

Работа содержит самостоятельный и содержательный результат, но научная доказательная база неполна.

Например:

- метод реализован;
- эксперименты проведены;
- есть количественные результаты;
- есть хотя бы базовое сравнение;
- показано преимущество или отличие предложенного подхода.

Но:

- недостаточный бейзлайн;
- отсутствует часть важных сравнений;
- недостаточно экспериментов;
- нет полноценного анализа вклада компонентов (ablation study);
- не до конца доказана научная новизна;
- недостаточно хорошо сформулирована гипотеза;
- препринт требует существенной доработки.

Проект уже представляет собой реальную научно-исследовательскую работу, но пока не является полноценным завершённым исследованием.

### 3D — минимально достаточный научный результат

Работа демонстрирует понимание предметной области и содержит некоторый собственный результат, однако исследование существенно неполное.

Характерно:

- задача актуальна;
- реализован некоторый метод;
- проведены отдельные эксперименты;
- получены результаты;
- студент понимает базовую идею решения.

Но:

- экспериментов недостаточно;
- сравнение с аналогами ограничено или слабое;
- бейзлайн отсутствует либо выбран некорректно;
- метрики недостаточно обоснованы;
- научная новизна сформулирована неубедительно;
- результаты недостаточно подтверждены;
- артефакты требуют значительной доработки.

Работа показывает, что исследование начато и определённый результат получен, но научная часть ещё не доведена до полноценного уровня.

### 3E — пограничный научный результат

Есть признаки выполненной работы, но результат находится на минимально приемлемом уровне.

Например:

- сформулирована задача;
- проведена реализация;
- имеются отдельные результаты;
- студент может объяснить основные этапы работы.

Однако:

- эксперименты крайне ограничены;
- сравнение с аналогами отсутствует или практически неинформативно;
- метрики выбраны формально;
- научная новизна фактически не продемонстрирована;
- выводы существенно сильнее, чем позволяют результаты;
- артефакты неполные или низкого качества.

3Е не означает «почти 4». Это минимально приемлемый результат, который требует существенной доработки для превращения в полноценную исследовательскую работу.

### 2FX — неудовлетворительный научный проект

Оценка выставляется, если отсутствует убедительный результат, позволяющий оценить научное исследование.

Например:

- фактически отсутствует исследовательский результат;
- эксперименты не проведены или проведены формально;
- результаты представлены без анализа;
- студент не понимает методологию собственного исследования;
- отсутствует научная новизна;
- нет корректного сравнения;
- выводы не следуют из экспериментов;
- отсутствуют существенные артефакты;
- репозиторий не позволяет проверить заявленные результаты.

Типичная ситуация: «модель запустили на нескольких примерах, получили несколько чисел, но из этого невозможно сделать научный вывод».

Также 2FX автоматически выставляется, если не был найден руководитель на семестр/нет фидбека и оценки от руководителя перед защитой НИР.

Фидбек и оценка от руководителя является допуском до защит НИР.

## Технологический проект

### Что оценивается

- актуальность технологической задачи;
- качество постановки;
- техническая новизна;
- качество архитектуры;
- качество реализации;
- качество кода;
- воспроизводимость;
- тестирование;
- сравнение с существующими решениями;
- практическая ценность результата.

### 5А — технологическое решение высокого технического уровня, полностью соответствующее поставленной задаче и требованиям проекта

Создана полноценная работающая технологическая система, решающая актуальную задачу и демонстрирующая преимущества относительно существующих решений.

Обязательно:

- чётко определена технологическая проблема;
- обоснована её актуальность;
- проведён анализ существующих решений;
- сформулированы ограничения;
- реализовано самостоятельное техническое решение;
- проведено количественное сравнение с аналогами;
- используются релевантные метрики;
- показана практическая ценность решения;
- проведено тестирование;
- для сложных систем проведён анализ отдельных компонентов;
- репозиторий качественно организован;
- есть README;
- есть инструкции запуска;
- зависимости зафиксированы;
- присутствуют тесты;
- код структурирован;
- основные решения документированы;
- представлен качественный технологический отчёт;
- презентация позволяет быстро понять задачу, архитектуру и результаты;
- студент уверенно объясняет технические решения.

Просто работающая система без сравнения с аналогами не может получить 5А.

### 4В — сильный технологический результат

Работающая система качественно решает поставленную задачу.

Есть:

- самостоятельная реализация;
- хорошая архитектура;
- адекватное тестирование;
- рабочий репозиторий;
- документация;
- измеримые результаты;
- сравнение с некоторыми существующими решениями.

Недостатки могут заключаться в:

- неполном бенчмарке;
- недостаточном бейзлайне;
- ограниченном тестировании;
- недостаточной оптимизации;
- недостаточно глубоком анализе производительности.

При этом система является полноценным технологическим результатом.

### 4С — хороший технологический результат

Рабочий прототип создан и решает поставленную задачу, однако техническая проработка неполна.

Возможны:

- недостаточно качественная архитектура;
- слабое тестирование;
- ограниченная документация;
- недостаточно развитый интерфейс;
- небольшое количество сценариев;
- недостаточное сравнение с аналогами;
- отсутствие отдельных важных эксплуатационных характеристик.

Но результат реально работает и демонстрирует самостоятельную техническую работу студента.

### 3D — минимально достаточный технологический результат

Создан работоспособный прототип или отдельный технический компонент.

Однако:

- решение ограничено по функциональности;
- код требует существенной доработки;
- документация недостаточна;
- тестирование слабое;
- сравнение с аналогами ограничено;
- архитектура не полностью проработана;
- практическая применимость пока ограничена.

При этом результат можно запустить и продемонстрировать.

### 3E — пограничный технологический результат

Есть отдельные элементы реализации, но полноценный технологический результат практически не сформирован.

Например:

- написан код;
- проведены отдельные эксперименты;
- есть прототип;
- показан отдельный технический эффект.

Однако система:

- нестабильна;
- плохо документирована;
- практически не воспроизводима;
- не протестирована;
- не сравнена с аналогами;
- решает только небольшой фрагмент задачи.

### 2FX — неудовлетворительный технологический проект

Нет работающего или проверяемого технологического результата.

Код может отсутствовать, не запускаться либо не соответствовать заявленной задаче.

Также 2FX возможна, если:

- фактический результат существенно меньше заявленного;
- репозиторий содержит формальный или нерабочий код;
- нет доказательств работы системы;
- студент не может объяснить архитектуру;
- эксперименты отсутствуют;
- результат представляет собой набор чисел/скриншотов без работающего решения.

## Индустриальный проект

### Что оценивается

Индустриальный проект должен решать реальную или реалистичную практическую задачу, а не просто демонстрировать применение ML/LLM.

Оцениваются:

- актуальность задачи для индустрии;
- корректность постановки;
- понимание бизнес- или производственного контекста;
- качество технологического решения;
- потенциал внедрения;
- количественный эффект;
- сравнение с существующим процессом/решением;
- качество технической реализации;
- качество взаимодействия с индустриальным заказчиком.

### 5А — проект высокого уровня практической проработки, решающий актуальную индустриальную задачу и демонстрирующий высокий потенциал практического применения полученных результатов

Решение:

- отвечает актуальной задаче индустрии;
- имеет понятного пользователя/заказчика;
- решает конкретную проблему;
- имеет подтверждённую практическую ценность;
- количественно превосходит существующий подход или существенно улучшает процесс;
- имеет измеримый эффект;
- содержит сравнение с текущим процессом или существующими решениями;
- подтверждено представителем индустрии;
- имеет качественную техническую реализацию;
- имеет перспективу дальнейшего внедрения.

Обязательно представлены:

- качественная рецензия индустриального представителя;
- технический артефакт;
- описание проекта;
- презентация;
- количественные результаты.

Для 5А недостаточно написать: «решение может использоваться компанией».

Необходимо показать, почему оно нужно компании и какой эффект оно даёт.

### 4В — сильный индустриальный результат

Задача действительно актуальна для индустрии.

Создано работоспособное решение с понятным потенциалом применения.

Есть:

- количественные результаты;
- сравнение с существующим процессом;
- подтверждение заинтересованности индустриального партнёра;
- качественная реализация.

Но отсутствует часть доказательств промышленной готовности:

- не проведено полноценное пилотирование;
- нет оценки экономического эффекта;
- ограничен набор данных;
- недостаточно широкое тестирование.

### 4С — хороший индустриальный результат

Решение имеет понятную практическую ценность и работает, но его промышленная проработка ограничена.

Например:

- есть прототип;
- задача действительно существует;
- есть потенциальный пользователь;
- получены измеримые результаты.

Но:

- нет полноценного пилота;
- недостаточно сравнения;
- экономический эффект оценён приблизительно;
- инфраструктура внедрения не проработана;
- есть существенные технические ограничения.

### 3D — минимально достаточный индустриальный результат

Есть связь с реальной индустриальной задачей и некоторый результат.

Однако:

- задача сформулирована слишком широко;
- эффект не измерен;
- сравнение с существующим процессом слабое;
- прототип ограничен;
- подтверждение от индустрии недостаточно содержательное;
- внедрение пока малореалистично.

### 3E — пограничный индустриальный результат

Студент демонстрирует применение AI к потенциально практической задаче, но практически значимый результат не доказан.

Например:

- есть демонстрационный прототип;
- задача потенциально актуальна;
- есть отдельные результаты.

Однако нет:

- убедительного эффекта;
- сравнения с текущим процессом;
- подтверждения применимости;
- полноценной технической реализации.

### 2FX — неудовлетворительный индустриальный проект

Не доказана практическая актуальность решения либо отсутствует результат.

В частности:

- задача придумана формально;
- нет понятного индустриального пользователя;
- решение не связано с реальным процессом;
- эффект не измерен;
- прототип не работает;
- отсутствует необходимая рецензия;
- студент не может объяснить, зачем решение нужно индустрии.

## Коллаборативный проект

### Что оценивается

Коллаборативный проект оценивается не только по конечному результату, но и по индивидуальному вкладу студента.

Основные критерии:

- качество выполненной студентом части;
- самостоятельность;
- соблюдение сроков;
- способность работать с другими участниками;
- коммуникация;
- качество интеграции своей работы в общий проект;
- техническая/исследовательская сложность задач;
- понимание общего результата.

### 5А — студент демонстрирует высокий уровень командной работы и вносит самостоятельный и значимый вклад в общий результат проекта

Студент:

- выполняет содержательно сложную часть проекта;
- самостоятельно ставит и решает подзадачи;
- существенно влияет на общий результат;
- регулярно взаимодействует с командой;
- соблюдает сроки;
- качественно документирует свою работу;
- предоставляет воспроизводимый результат;
- понимает не только свою часть, но и место своей работы в общей системе;
- способен объяснить технические решения;
- демонстрирует высокий уровень профессиональных и soft skills.

Обязательно имеется подтверждение командного вклада.

При этом 5А не может быть поставлена только за участие в проекте.

### 4В — сильный командный вклад

Студент выполняет существенную часть проекта самостоятельно.

- задачи выполнены качественно;
- сроки соблюдаются;
- коммуникация эффективна;
- результат интегрирован в общий проект;
- студент способен объяснить свою работу;
- вклад заметно влияет на итоговый результат.

Есть отдельные недостатки в глубине, самостоятельности или коммуникации.

### 4С — хороший командный вклад

Студент выполняет поставленные задачи и является полноценным участником команды.

Однако:

- самостоятельность ограничена;
- часть задач требует постоянного контроля;
- документация недостаточна;
- есть проблемы со сроками;
- вклад менее значим, чем у сильных участников команды.

При этом студент выполняет свою часть и понимает её содержание.

### 3D — минимально достаточный командный вклад

Студент выполнил некоторый объём работы, но:

- требуется существенная помощь команды;
- задачи выполнены частично;
- сроки иногда нарушаются;
- вклад ограничен;
- есть проблемы с коммуникацией;
- недостаточно понимания общей архитектуры.

Тем не менее, вклад можно идентифицировать и он имеет отношение к итоговому проекту.

### 3E — пограничный командный вклад

Участие студента в проекте формально присутствует, но его вклад минимален.

Например:

- выполнены небольшие вспомогательные задачи;
- часть задач переделывали другие участники;
- сроки существенно нарушались;
- студент слабо взаимодействовал с командой;
- вклад сложно отделить от работы других участников.

### 2FX — неудовлетворительный командный вклад

Студент фактически не выполнил свою часть проекта либо невозможно подтвердить его вклад.

Например:

- задачи не выполнены;
- результат не интегрирован;
- студент не может объяснить свою часть;
- существенную работу выполнили другие участники;
- студент систематически нарушал сроки;
- отсутствовала коммуникация;
- вклад невозможно подтвердить.

## Групповой проект

Групповой проект отличается от коллаборативного тем, что единый проект должен иметь масштаб, соответствующий суммарному объёму работы всех участников.

Для группы из N человек проект должен быть сопоставим по объёму и сложности с N индивидуальными проектами.

При этом оцениваются одновременно:

1. качество общего результата;
2. масштаб проекта;
3. сложность проекта;
4. вклад каждого участника;
5. интеграция отдельных компонентов.

### 5А — выдающийся групповой результат

Группа создала комплексный результат, который по масштабу соответствует суммарной работе участников и демонстрирует высокий уровень по содержанию.

Обязательно:

- задача актуальна;
- масштаб соответствует числу участников;
- у каждого участника есть самостоятельная содержательно значимая зона ответственности;
- индивидуальный вклад каждого участника может быть идентифицирован;
- компоненты интегрированы в единый результат;
- проведено количественное сравнение с существующими решениями;
- используются релевантные метрики;
- для сложной системы проведён анализ вклада компонентов;
- результат воспроизводим;
- репозиторий качественный;
- есть документация;
- представлены все обязательные артефакты;
- есть индивидуальные отчёты участников;
- презентация показывает как общий результат, так и вклад участников;
- каждый участник способен объяснить свою часть и взаимосвязь с другими частями;
- группа демонстрирует качественную командную работу.

Ключевое условие: нельзя получить 5А за проект одного человека, искусственно разделённый между несколькими студентами.

### 4В — сильный групповой результат

Создан полноценный комплексный проект.

- масштаб соответствует большинству требований к группе;
- работа распределена между участниками;
- компоненты интегрированы;
- получены измеримые результаты;
- есть сравнение с существующими решениями;
- репозиторий и документация находятся на хорошем уровне;
- большинство индивидуальных вкладов содержательно значимы.

Недостатки могут касаться:

- неполного benchmark;
- отдельных слабых компонентов;
- недостаточного количества экспериментов;
- неидеальной интеграции;
- неравномерности вкладов.

### 4С — хороший групповой результат

Проект имеет достаточный масштаб и является действительно групповым.

- несколько самостоятельных компонентов разработаны;
- общий результат работает;
- вклад участников можно идентифицировать;
- есть базовые количественные результаты;
- присутствует сравнение с отдельными аналогами.

Но:

- некоторые части существенно менее проработаны;
- интеграция неполная;
- эксперименты ограничены;
- документация недостаточна;
- индивидуальный вклад отдельных участников недостаточно содержателен.

### 3D — минимально достаточный групповой результат

Проект содержит несколько частей, выполненных разными участниками, однако его масштаб или качество недостаточны.

Например:

- общий результат существует;
- участники выполнили разные задачи;
- есть работающий прототип.

Но:

- общий объём недостаточен для заявленного количества участников;
- часть участников выполняла только вспомогательную работу;
- компоненты плохо интегрированы;
- мало экспериментов;
- слабое сравнение;
- репозиторий недостаточно качественный.

### 3E — пограничный групповой результат

Формально проект является групповым, но фактически не соответствует требуемому масштабу.

Например:

- несколько участников работают над одной небольшой задачей;
- большая часть работы выполнена одним-двумя участниками;
- индивидуальные вклады трудно выделить;
- итоговый результат небольшой;
- интеграция формальная;
- количественная оценка слабая.

Проект может быть засчитан как минимально выполненный, но требует существенной доработки.

### 2FX — неудовлетворительный групповой проект

Оценка выставляется, если:

- отсутствует единый работающий результат;
- объём проекта существенно меньше суммарного объёма, соответствующего числу участников;
- индивидуальный вклад невозможно определить;
- значительная часть заявленных работ не выполнена;
- компоненты не интегрированы;
- отсутствуют необходимые артефакты;
- нет доказательств работоспособности;
- участники не могут объяснить собственный вклад;
- проект фактически представляет собой одну небольшую индивидуальную работу, формально объявленную групповой.

# Критерии артефактов

## Качество кода и репозитория

Качество репозитория является отдельным критерием для всех проектов, в которых присутствует программная реализация.

### Уровень 5А

Репозиторий:

- имеет понятную структуру;
- содержит информативный README;
- описывает постановку задачи;
- содержит инструкцию по установке;
- содержит инструкцию по запуску;
- позволяет воспроизвести основные эксперименты;
- фиксирует зависимости;
- содержит конфигурационные файлы;
- содержит тесты там, где они необходимы;
- код модульный и читаемый;
- отсутствуют очевидные дублирования;
- названия переменных и функций понятны;
- история разработки позволяет увидеть реальную работу (должна быть история коммитов в течение всего семестра);
- результаты экспериментов организованы;
- секреты и API-ключи не хранятся в репозитории;
- присутствует документация архитектуры, если система сложная.

### Уровень 4В

Репозиторий хорошо организован и позволяет запустить решение, но отдельные элементы документации, тестирования или структуры требуют улучшения.

### Уровень 4С

Код работает, но репозиторий имеет заметные проблемы:

- слабая документация;
- сложный запуск;
- недостаточная модульность;
- мало тестов;
- неочевидная структура.

### Уровень 3D

Код позволяет продемонстрировать отдельный результат, но воспроизводимость ограничена.

### Уровень 3E

Код существует, однако запуск и проверка результата существенно затруднены.

### 2FX

Код отсутствует, не запускается, не соответствует заявленному решению или не позволяет проверить результат.

## Качество презентации и защиты

Презентация оценивается отдельно от содержания проекта.

### 5А

Презентация:

- имеет ясную структуру;
- быстро вводит в проблему;
- объясняет актуальность;
- показывает существующие решения;
- формулирует gap;
- объясняет собственный вклад;
- содержит архитектуру/метод;
- показывает экспериментальный дизайн;
- содержит количественные результаты;
- содержит сравнение с аналогами;
- показывает ограничения;
- делает выводы строго из полученных данных.

Докладчик:

- не читает текст со слайдов;
- говорит самостоятельно;
- отвечает на вопросы;
- понимает детали работы;
- не уходит от замечаний комиссии;
- способен объяснить, почему получены именно такие результаты.

### 4В

Презентация:

- имеет ясную и последовательную структуру;
- понятно вводит в проблему и объясняет её актуальность;
- описывает основные существующие решения;
- объясняет, какую задачу решает предложенный подход;
- формулирует основной вклад проекта;
- содержит описание архитектуры/метода;
- описывает основные этапы эксперимента;
- содержит количественные результаты;
- содержит сравнение с основными аналогами;
- корректно интерпретирует основные результаты;
- содержит основные выводы;
- в целом позволяет комиссии оценить качество и значимость полученного результата.

Докладчик:

- в основном говорит самостоятельно, а не читает текст со слайдов;
- хорошо ориентируется в содержании работы;
- может объяснить основные принятые решения;
- отвечает на основные вопросы комиссии;
- может интерпретировать представленные результаты;
- понимает основные ограничения своего решения;
- может объяснить причины основных полученных результатов;
- при этом может испытывать затруднения при ответе на отдельные углублённые или неожиданные вопросы.

**5А** — всё выше + глубокое понимание и убедительная аргументация, включая ограничения, причины результатов и сложные вопросы.

**4В** — все основные элементы качественно представлены и студент уверенно защищает работу, но глубина анализа/ответов немного не дотягивает до отличного уровня.

**4С** — основное содержание есть, но уже появляются заметные проблемы с качеством представления или защиты: нарушается логика, плохо показаны результаты, мотивация недостаточна, ответы не всегда уверенные.

### 4С

Основное содержание понятно, но:

- часть результатов плохо визуализирована;
- логика изложения местами нарушена;
- недостаточно хорошо показана мотивация;
- ответы на вопросы не всегда уверенные.

### 3D

Презентация позволяет понять общую идею, но:

- слишком много текста;
- недостаточно результатов;
- плохо объяснена методология;
- логика изложения нарушена;
- ответы на вопросы поверхностные.

### 3E

Презентация формально содержит информацию о проекте, но практически не позволяет оценить качество результата.

Докладчик:

- плохо ориентируется в работе;
- не может объяснить отдельные решения;
- не отвечает на существенные вопросы.

### 2FX

Защита не позволяет установить, что студент понимает и выполнил заявленную работу.

Например:

- студент не может объяснить метод;
- не знает, что сравнивалось;
- не знает используемые метрики;
- не может объяснить результаты;
- существенная часть презентации представляет собой автоматически сгенерированный текст;
- ответы на базовые вопросы отсутствуют.

# Принцип «недостаточно просто сделать»

При выставлении оценки комиссия оценивает не только наличие результата, но и доказанность его качества.

Недостаточно:

- реализовать модель;
- получить одну метрику;
- показать красивый график;
- сравнить две версии собственного метода;
- показать, что «наша модель лучше бейзлайна» без объяснения бейзлайна;
- заявить, что решение «новое»;
- заявить, что решение «можно использовать в индустрии»;
- показать работающий прототип без анализа существующих аналогов.

Необходимо показать:

**задача → актуальность → существующие решения → пробел в исследованиях → собственный вклад → метод → эксперимент → метрики → сравнение → анализ → вывод.**

Для сложных систем:

**система → компоненты → вклад каждого компонента → анализ вклада компонентов (ablation study) → сравнение с аналогами → итоговый эффект.**

# Ограничения максимальной оценки

Для единообразия оценивания предлагается установить следующие формальные ограничения:

| Ситуация | Максимальная оценка |
|---|---|
| Не представлены все обязательные артефакты | не выше 4В |
| Нет количественного сравнения с существующими аналогами | не выше 4С |
| Нет ни одного содержательного бейзлайна/аналога | не выше 3D |
| Для сложной многокомпонентной системы нет анализа вклада компонентов | не выше 4С |
| Студент не может объяснить существенную часть собственной работы | не выше 3D |
| Не доказана актуальность задачи | не выше 4С |
| Нет работающего/проверяемого результата | не выше 3E, а при отсутствии содержательного результата — 2FX |
| Репозиторий не позволяет проверить заявленный результат | не выше 4С |
| Для индустриального проекта отсутствует обязательная оценка/рецензия индустриального партнёра | не выше 4В |
| Для группового проекта объём существенно меньше суммарного объёма работы участников | не выше 4С |
| Для группового проекта невозможно определить индивидуальный вклад | не выше 4С |
| Презентация не позволяет понять постановку, метод и результаты | не выше 4С |
| Студент не способен ответить на базовые вопросы по своей работе | не выше 3D |

Важно: наличие формального артефакта не означает выполнение соответствующего требования. Например, наличие README из нескольких строк не означает наличие качественной документации, а наличие таблицы с числами не означает наличие корректного экспериментального сравнения.

# Принцип выставления итоговой оценки

Итоговая оценка должна определяться по наиболее слабым критически важным компонентам, а не как простое среднее арифметическое.

Например, проект может иметь:

- отличный код;
- отличную презентацию;
- хорошо работающий прототип;

но если для 5А отсутствует сравнение с аналогами по метрикам, итоговая оценка не может быть 5А.

Аналогично, научный проект с интересной гипотезой, но без экспериментов не может получить высокую оценку только за потенциальную новизну.

Таким образом, 5А присваивается только результату, для которого одновременно доказаны актуальность, качество, новизна/практическая ценность, экспериментальная состоятельность, преимущество или отличие от существующих решений, качество артефактов и понимание результата студентом.

# Как использовать матрицу на защите

Комиссии рекомендуется не начинать с вопроса: «Какую оценку поставить?»

Вместо этого необходимо последовательно пройти четыре шага.

## Шаг 1. Оценить обязательные критерии

Отметить:

- задача актуальна;
- задача корректно поставлена;
- существующие решения проанализированы;
- есть количественные метрики;
- есть сравнение с аналогами;
- результат действительно получен;
- экспериментальная/практическая проверка проведена;
- все обязательные артефакты представлены;
- код/репозиторий проверяемы;
- презентация позволяет оценить результат;
- студент понимает собственную работу.

## Шаг 2. Выбрать уровень по каждому критерию

Для каждого критерия комиссия выбирает: **5А / 4В / 4С / 3D / 3E / 2FX**.

## Шаг 3. Проверить ограничители

После выставления уровней необходимо проверить:

- нет ли отсутствующего обязательного артефакта;
- есть ли сравнение с аналогами;
- используются ли метрики;
- доказана ли актуальность;
- воспроизводим ли результат;
- понимает ли студент собственную работу;
- выполнены ли специальные требования конкретного типа проекта.

## Шаг 4. Определить итоговую оценку

Итоговая оценка не должна автоматически рассчитываться как среднее арифметическое.

Используется следующий принцип:

> Итоговая оценка отражает наиболее высокий уровень, для которого выполнены все критические требования соответствующего уровня.

То есть для получения 5А недостаточно иметь средний уровень «5А». Необходимо выполнить все обязательные условия 5А.

# Быстрый чек-лист для членов комиссии

## Можно ли поставить 5А?

Все ответы должны быть «да».

- [ ] Задача действительно актуальна?
- [ ] Актуальность доказана, а не просто заявлена?
- [ ] Есть чёткая постановка и критерии успеха?
- [ ] Проанализированы существующие решения?
- [ ] Есть релевантный бейзлайн/аналоги?
- [ ] Есть количественные метрики?
- [ ] Есть количественное сравнение с аналогами?
- [ ] Сравнение проведено в сопоставимых условиях?
- [ ] Результат превосходит/дополняет аналоги и это доказано?
- [ ] Для сложной системы проведён анализ компонентов?
- [ ] Все обязательные артефакты представлены?
- [ ] Репозиторий качественный и воспроизводимый?
- [ ] Код соответствует заявленному результату?
- [ ] Презентация качественно показывает результат?
- [ ] Студент понимает собственную работу?
- [ ] Студент способен ответить на вопросы комиссии?
- [ ] Выполнены специальные требования типа проекта?

Если хотя бы один ответ «нет», 5А не выставляется.

# Быстрый чек-лист для различения 4В и 4С

## 4В

Проект:

- полностью работает;
- имеет самостоятельный результат;
- имеет количественные результаты;
- имеет сравнение с аналогами;
- имеет качественные артефакты;
- имеет хороший репозиторий;
- хорошо защищён;
- имеет только отдельные, а не системные недостатки.

## 4С

Проект:

- работает;
- имеет содержательный результат;
- демонстрирует самостоятельную работу;
- имеет хотя бы базовую экспериментальную проверку;

но:

- сравнение ограничено;
- экспериментальная база неполна;
- есть проблемы с артефактами/кодом/документацией;
- презентация или защита имеют заметные недостатки;
- отдельные важные требования не выполнены.

# Быстрый чек-лист для различения 3D и 3E

## 3D

«Работа действительно сделана, но существенно недоделана».

Есть:

- рабочий результат;
- самостоятельная работа;
- базовая проверка;
- понятная задача.

Но значительная часть требований не выполнена.

## 3E

«Есть признаки работы, но полноценного результата практически нет».

Есть:

- отдельные реализации;
- отдельные эксперименты;
- частичный результат.

Но проект не позволяет убедительно доказать качество решения.

# При сомнении между двумя оценками

Необходимо задавать вопрос: **«Чего не хватает?»**

## 4В → 4С

- более сильного бейзлайна;
- количественного сравнения;
- экспериментов;
- лучшего качества репозитория;
- более убедительного анализа;
- более качественной презентации.

## 5А → 4В

- полноценного сравнения с релевантными аналогами;
- количественного преимущества/значимого результата;
- качественного экспериментального дизайна;
- анализа компонентов;
- воспроизводимости;
- высокого уровня презентации и защиты;
- выполнения всех специальных требований типа проекта.
