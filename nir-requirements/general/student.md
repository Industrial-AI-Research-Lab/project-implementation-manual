# General NIR and Project Requirements — Student Guide

## Core principle

A project is evaluated not merely on whether something was produced, but on how convincingly the quality, independence, and usefulness of the result are demonstrated.

The basic logic of a strong project is:

**problem → relevance → existing solutions → gap or limitation → original contribution → method or implementation → experiment or practical validation → metrics → comparison → analysis → conclusion.**

For a complex multi-component system, also include:

**system → components → contribution of each component → ablation or component analysis → comparison with alternatives → overall effect.**

## What every strong project must include

- Relevance is demonstrated through a scientific, technological, or industrial context rather than merely asserted.
- The problem statement is specific: inputs, outputs, constraints, and success criteria are clear.
- Relevant alternatives, baselines, and/or state-of-the-art approaches are analyzed.
- The project produces a substantive original result rather than merely running a ready-made solution.
- Quantitative validation uses justified metrics.
- Comparisons use identical or comparable conditions.
- Results are interpreted, not merely shown: explain why they occurred, where the solution is stronger or weaker, and what its limitations are.
- Another researcher or developer can reproduce the result.
- Every mandatory project artifact has substantive content rather than existing as a formality.
- At the defense, the student can independently explain the problem statement, method, architecture, metrics, baselines, results, and limitations.

## What is critical for a 5A grade

A 5A grade requires all of the following:

1. every mandatory artifact for the selected project type;
2. quantitative comparison with relevant existing solutions;
3. reproducibility;
4. independent understanding of one's own work; and
5. fulfillment of the selected project type's specific requirements.

The final grade is not an arithmetic mean. A single critical failure may cap the maximum grade.

### Formal caps

- not all mandatory artifacts are present → maximum **4B**;
- no quantitative comparison with alternatives → maximum **4C**;
- no substantive baseline or alternative → maximum **3D**;
- no analysis of component contributions for a complex system → maximum **4C**;
- the student cannot explain a substantial part of the work → maximum **3D**;
- relevance has not been demonstrated → maximum **4C**;
- no working or verifiable result → maximum **3E**, or **2FX** when no substantive result exists;
- the repository does not make the result verifiable → maximum **4C**;
- the presentation does not communicate the problem, method, and results → maximum **4C**; and
- the student cannot answer basic questions → maximum **3D**.

## Repository and reproducibility

For software projects, the repository is evaluated separately. A high-quality repository is expected to provide:

- a clear structure;
- a substantive README containing the problem statement;
- installation and launch instructions;
- pinned dependencies and configurations;
- a way to reproduce the main experiments or results;
- tests where needed;
- modular and readable code;
- organized experiment results;
- architecture documentation for a complex system;
- no secrets or API keys; and
- a semester-long commit history demonstrating genuine work on the project.

## Presentation and defense

A strong presentation quickly communicates:

**problem → relevance → alternatives → gap → original contribution → method or architecture → experiment → quantitative results → comparison → limitations → conclusions.**

At the defense, the student should explain decisions and answer questions independently rather than read the slides. This includes explaining the causes of the observed results and the solution's limitations.

## Artifacts

The exact set depends on the project type. A presentation is almost always the minimum. Scientific and technological projects also require a substantive written artifact and a public repository; an industrial project requires a review by an industry representative; and a collaborative project requires an assessment of the team contribution.

A formal link alone does not satisfy an artifact requirement. The artifact's content must make the claimed result verifiable.

## Organizational provisions

A project is treated as a complete semester-long work. The student builds a portfolio of several completed projects and may continue the topic with the same supervisor. At the end of the project, the student presents a presentation and the additional artifacts required for that project type.

The defense may also consider achievements beyond the mandatory results, including publications, patents, deployment certificates, high-quality technology articles, and the popularity of open-source software.

## Use of generative AI

Generative AI is permitted except for falsification of results. Students bear the same responsibility for errors introduced with AI as for their own errors. Effective and substantive use of AI may be considered an additional achievement.
